# ブログトーク 番組仕様

平日12時放送の座談会番組「ブログトーク」の仕様と、生成に使うファイルの対応表。
このファイル自体はプロンプトとして使わない（目次と設計メモ）。

## 番組
- 枠: 平日（月〜金）12:00、30〜45分（原稿 7000〜8500字が目安）
- 内容: ブログ「ねるると鍵鷺優の徒然日記」の記事を1本取り上げ、3人で掘り下げる
- 話者: めたん（進行）／つむぎ（質問役）／ずんだもん（解説役）— ガジェットマニアと同配役
- 著者のことは「優さん」と呼ぶ。本人は登場しない
- 流れ: オープニング → 記事のあらまし → 深掘り（3つの山）→ 感想戦 → 締め

## 生成の仕組み（セクション分割方式）
1回の LLM 呼び出しでは長尺が出ないため、ガジェットマニアと同じく
セクションごとに分けて生成し、最後に結合する。

| 段階 | プロンプト | 役割 |
|---|---|---|
| 素材抽出 | blog-talk-extract.md | 記事 → 素材JSON（あらまし／山3つ／読み） |
| オープニング | blog-talk-opening.md | 挨拶・記事紹介・山の予告（800〜1200字） |
| 深掘り | blog-talk-deep.md | 1つの山を掘る（1800〜2500字）。山の数だけ繰り返す |
| クロージング | blog-talk-closing.md | 感想戦と締め（800〜1200字） |

## コード
- `py/tools/make_blog_talk.py`: 上の4段階を実行し、結合 → 読み辞書 → 英字の自動解決まで行う
- `py/tools/run_blog_job.py`: 記事選び（未使用記事のローテーション）→ make_blog_talk → 音声化して `blog_talk_latest.mp3` を置く
- スケジューラ登録: `run_scheduler.py` の BLOG_JOBS（平日 11:50）

## 運用メモ
- 尺は記事の濃さに左右される。薄い記事の日は短くなってよい（無理な水増しをしない）
- 記事プールが尽きたらローテーションは自動でリセットされる
