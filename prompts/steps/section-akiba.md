# 構成
- 最低3400字、発言は最低30回（上限はない）
- 素材の "articles" の2本を、1本ずつ順に扱う。1本ごとに、素材の "points" の3つを、1つずつ順に扱う。1つの要点ごとに、次の順に書く
  1. めたんが、記事に書いてあることを紹介する（2文まで。このコーナーだけは、めたんが記事の内容を説明してよい）
  2. つむぎが素朴な疑問や驚きでリアクションする
  3. ずんだもんが、スペックや特徴の意味を解説し、自分の意見を言う
  4. 必要なら、つむぎの質問とずんだもんの答えを1〜2往復足す
- 要点を1つ扱うごとに、短くまとめずに次へ進む。3つ扱い終わったら、次の記事へ移る（移るときは、めたんが素材の "title_spoken" でタイトルを紹介する）
- 記事の内容を伝える発言は、すべてめたんがする。ずんだもんは、めたんが紹介した内容への意見・用語の説明・関連する話だけをし、記事の内容を伝える言い方（記事によると、記事では、筆者は など）を使わない
- 用語の説明は、めたんではなくずんだもんがする。つむぎが用語を聞き返したら、次の発言でずんだもんが答える（めたんが取り次がない）
- 聴き手が知らない略語は、初めて出たときに、ずんだもんが正式名か意味を添える。よく知られた略語はそのまま使う。型番は素材の "readings" の読みで言う
- ずんだもんは聞き役にならない。記事の内容を知らない側に回らない
- 早口の場面は入れない（このコーナーは落ち着いて深堀りする）
- 最後の発言はつむぎにし、2本のニュースを聞いた感想を身近なものにつなげる前向きな一言にする。そのあとに誰の発言も書かない。めたんは、締めの一言を求める振りをしない

# 記事の内容と意見を分ける（重要）
- 記事に書いてあること（"points" と "details" の内容）は、めたんが「記事によると」のように、記事の内容だと分かる形で話す
- 記事に書いていない解釈・推測・一般論は、「ボクは〜だと思うのだ」「〜なのかしら」のように、話している人の意見だと分かる形で話す。記事の主張として語らない
- 素材にない記事の内容（スペックの細部、価格、発売日、著者の意図など）を作らない。価格や発売日に触れるときは、素材の "details" にある範囲だけにする
- 同じ要点を、言い方を変えて2回以上繰り返さない

# 守ること
- お礼の言葉（「お聴きいただきありがとうございます」など）やコーナーの締めの挨拶は言わない（このあとにブログピックアップが続くため）
- 誰も、つむぎの家族・家・持ち物・自分のブログなどを話題にしない（つむぎ自身も話さない）
- 同じ人が2回続けて話さない
- めたんの発言は2文まで。「では」で始まる発言はこのコーナーで1回まで
- 「いい質問」はこのコーナーで1回まで。つむぎが実際に質問した直後だけ使う
- 素材にない数値・歴史・因果関係を足さない
